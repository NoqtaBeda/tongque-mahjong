# 番种统计流水线

一条命令链，四张图，发 QQ。**默认 16 片并行**。

## 0. 前置

- 工作目录：仓库根（本项目）。数据源与产物都在 `.data/`（已 gitignore）。
- Python 用工作区自带的运行时，路径由 `load_workspace_dependencies` 给出（`python` 字段）；不要用 PATH 里的 python，可能缺 Pillow。
- 权重：自动用 `packages/core/src/ai/nn/weights.ts`（= 当前线上最优 AI）。**不需要**任何模型参数。

## 1. 跑自对弈统计

```powershell
node scripts/yaku-stats.ts --games=<N> --jobs=16 --seed=202611200030
```

- `--jobs=16` 是默认；机器核数少或已在跑别的重任务时降到 8。
- **种子必须是纯数字**（用 `yyyymmddHHmmss` 打头，例如 `202611200030`）。脚本现在会拒绝非数字种子——曾经用 `y2026...` 跑出过退化对局（自摸 0、只出现 6 种番种），排查很久。
- 快速自检（1 分钟内）：`--games=400 --jobs=16`，应当看到自摸数 > 0、番种 30 种以上、和牌率约 70–76%。
- 耗时参考：40,000 局 ≈ 22 分钟（16 片）；每片必须是整数局（`--games` 要能被 `--jobs` 整除）。
- 产物：`.data/yaku-stats-last.json`，并打印两张文本表（番种表 + 得分分布）。

要点（写报告时会用到）：
- **出现率** = 该番种出现的和牌手数 / 和牌总手数（不是 / 本场数）。
- **得分 S** 可能超过 12：规则是 `S = (∃单个番种≥12) ? 该番种 : min(12, Σ)`，所以会出现 13（十三幺）、16、24。
- 和牌手数 + 流局数 − 本场数 = **一炮多响**的本场数，解释百分比时别当成数据错误。

## 2. 出四张图

```powershell
& <python> tools/charts/yaku-tables.py     # → .data/番种统计-按出现率.png、.data/番种统计-按分值.png
& <python> tools/charts/score-bars.py      # → .data/得分分布-等于.png、.data/得分分布-小于等于.png
```

两张表的配色约定（改脚本时保持一致）：
- **番种名**用 UI 的分值色阶（灰绿1 / 绿2 / 黄绿4 / 黄6 / 橙8 / 桔红12 / 粉16 / 紫24），左侧小方块同色。
- **出现率**用独立的频次色阶：**绿 = 常见 → 橙 → 红 → 紫 = 稀有**，按对数映射。两套色阶不得混用。
- 表里出现率 ≥0.01% 保留两位，更小的用三位，否则稀有番种会全显示 0.00%。

## 3. 发到 QQ

四张图逐个发送（文件名含中文可以直接发）：

```
qqbot_send_file(file_path="<仓库根>\\.data\\番种统计-按出现率.png")
qqbot_send_file(file_path="<仓库根>\\.data\\番种统计-按分值.png")
qqbot_send_file(file_path="<仓库根>\\.data\\得分分布-等于.png")
qqbot_send_file(file_path="<仓库根>\\.data\\得分分布-小于等于.png")
```

然后发一条 `qqbot_send_text`：局数/本场/和牌手数/和牌率/平均打点，最常出现的三个番种，`≥12 分`占比，以及 5 分档低于 6 分档这类结构性现象。不写没算过的数字。

路径限制：`im-qqbot` 的 `sendFile.restrictPaths` 已关闭，工作区内任意路径都能直接发；若哪天又报“不在允许的目录内”，先看 `.dsh` profile 的 `cordis.patch.yml` 该字段。

## 3.5 怀疑随机性时（可选）

```powershell
node scripts/check-rng.ts --walls=20000              # 4 人
node scripts/check-rng.ts --walls=8000 --preset=3p   # 三人（有字/无字都支持）
```

体检项：同种子可复现、每个牌山位置的牌种均匀性（卡方）、第 1 张与起手 13 张分布、
连号种子的独立性、同场相邻轮次的独立性、牌山去重。全部落在随机范围内才算通过。
历史结论（2026-11-20）：4 人 2 万张牌山、三麻 8000 张，各项均通过。

随机源现状：引擎用 xoshiro128\*\*（128 位状态，`GameState.rng`）。脚本里的数字种子仍是 32 位
（保持老数据可复现），需要更大空间时传 bigint 或字符串种子；真实对局由 `randomRng()`
取 `crypto.getRandomValues` 的 128 位系统熵。

## 4. 收尾

- 图在 `.data/`，不提交。
- 报告里注明：局数、并行片数、耗时、种子，方便复现。

## 常见坑

- `--games` 不能整除 `--jobs` 会报错并退出（分片必须均分）。
- 分片脚本自己按 `--shard=i/n` 切片，**父进程要传总 `--games` 和基础 `--seed`**；若改成传每片局数，会变成“每片只跑 1/16”。
- 统计脚本里番种按 key 聚合、同一手牌同一番种只记一次；`points` 取出现过的最大值（一杠/两杠这类同名不同分）。
- 画图脚本若报 `anchor not supported for multiline text`，说明标签里放了换行，改成两次 `draw.text`。
