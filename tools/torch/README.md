# PyTorch 训练管线

用 PyTorch 训练 `进阶` 档的估值网络，产物仍然是 `packages/core/src/ai/nn/weights.ts`，
推理端继续用 `packages/core/src/ai/nn/mlp.ts` 的纯 TS 前向。

## 环境

已在 Windows + RTX 3060 上验证：

| 项 | 版本 |
| --- | --- |
| Python | 3.15.2 |
| PyTorch | 2.15.0+cu134 |
| CUDA | 可用 |

## 完整流程

```bash
# 1. 生成训练数据（与 TS 训练器共用同一份 .bin 格式）
node tools/train/gen.ts --games=5000 --preset=4p --seed=210000 --out=.data/chunk-210000.bin
#    想快就并行开几份，不同 seed / 不同 out

# 2. 训练（逗号分隔多个数据文件；默认写到线上权重位置）
python tools/torch/train.py --data=.data/chunk-1.bin,.data/chunk-2.bin --epochs=30
#    先写到候选文件、评测满意再上线：
python tools/torch/train.py --data=... --out=.data/cand.ts

# 3. 上线（会重写 import 路径并做基本校验）
python tools/torch/install_weights.py --from .data/cand.ts

# 4. 数值一致性：PyTorch 前向 == TS 前向
npm run check:parity

# 5. 实战对照：进阶档 vs 普通档
node scripts/eval.ts --games=1024 --seed=777
```

## 脚本一览

| 文件 | 作用 |
| --- | --- |
| `model.py` | 读 `.bin`、按本场分组切分、模型定义、相关系数 |
| `train.py` | 训练器，带早停和三分割（train/val/test） |
| `smoke.py` | 冒烟测试：确认环境能跑通、看吞吐 |
| `export_weights.py` | `state_dict` → `weights.ts`（base64 的 float32 字节流） |
| `install_weights.py` | 候选权重装到线上位置（重写 import、校验文件完整） |
| `parity.py` | 生成参考输入与前向结果，供 `scripts/nn-parity.mjs` 比对 |

## 实测记录

同样的 120 维特征、同样的 `potential = 6000`，只加数据、把网络换成 PyTorch 训练：

| 训练样本 | 参数量 | 测试集 r | 实战 vs 普通（seed 777） |
| --- | --- | --- | --- |
| 360k（TS 训练器） | 23,809 | 0.252 | +1.73 分/局 |
| 480k | 23,809 | 0.270 | +2.54 |
| 960k | 23,809 | 0.284 | +3.13 |
| 1.44M | 23,809 | 0.301 | +3.24 |
| 2.40M | 23,809 | 0.322 | +3.57 |
| 3.36M | 23,809 | 0.327 | +3.33 |

2.4M 那版跨三个种子的复测是 **+3.57 / +3.28 / +3.46**（均值 +3.44）；
3.36M 是 **+3.33 / +3.47 / +3.40**（均值 +3.40）。到 2.4M 以后基本进入平台，
再翻倍数据只把测试集 r 从 0.322 抬到 0.327，实战看不出差别。

几条扫描结论：

- **模型变大没用**：512/256（19.4 万参数）测试集 r 0.289，反而略低于 128/64 的 0.284→0.322 曲线，
  实战 960k 时是 512/256 的 +2.99 对 128/64 的 +3.13。**选小的**，体积和推理都快 8 倍。
- **weight decay 有害**：1e-4 就把 r 从 0.270 压到 0.193。
- **学习率和 batch 不敏感**：lr 1e-3 / 3e-3、batch 256 / 1024 之间差 0.01 以内。
- **权重系数没漂**：给新网络重扫 `potential`，4000 / 6000 / 8000 / 12000 分别是
  +2.43 / +2.54 / +2.55 / +2.52，6000 仍在平台上。

## 策略迭代（用进阶档自己产数据）

数据生成器支持 `--level=advanced`，可以让**进阶档自己打**、用它的局面产数据。

第一轮实验（普通数据已经堆到 336 万，模型接近饱和）：

| 数据集 | 样本 | 实战 vs 普通 |
| --- | --- | --- |
| 纯普通档数据 | 3.36M | +3.33 |
| 纯进阶档自对弈 | 384k | +3.35 |
| 进阶自对弈 + 普通数据 | 3.74M | +4.22 |

**38 万进阶自对弈样本 ≈ 336 万普通样本**，数据效率差近 9 倍——进阶档走到的局面
才是它自己真正会遇到的分布。

### 多轮迭代（每轮都用当前最强的模型重新产数据）

后来把普通数据的量降下来、把进阶自对弈的占比提上去，多轮迭代是持续有效的：

| 轮次 | 普通数据 | 进阶自对弈 | 总样本 | 三种子均值 |
| --- | --- | --- | --- | --- |
| 1 轮 | 480k | 576k | 1.06M | +4.19 |
| 2 轮 | 480k | 1.15M | 1.44M | +4.22 |
| **3 轮** | 480k | 1.73M | **2.02M** | **+4.68** |

关键不是总样本数，而是**进阶自对弈数据的占比**：同样是 100 万出头，进阶占比 55% 的模型
（+4.16）能追平 374 万样本、进阶占比只有 10% 的模型（+4.22）。

> 注意别和前一次的"第二轮没提升"混淆：那次是在 336 万普通数据之上加一轮，
> 模型早被海量普通数据喂饱和了。数据量降下来以后，多轮迭代才重新变得有效。

## 几个容易踩的点

- **`w1` 不需要转置**：TS 侧的 `w1` 是 `dim1 × dim0` 行主序，PyTorch 的 `Linear.weight` 也是
  `(out, in)`，直接按行展平即可。
- **必须按本场分组切分**：同一本场的样本共享同一个标签，按行随机切分会让验证集泄漏，
  相关系数会虚高到 0.8 以上。
- **必须有独立测试集**：早停是从验证集里挑轮次，挑出来的轮次"看过"验证集，
  报出来的数会偏高。`train.py` 的三分割里测试集不参与早停，那个数才能跟别的配置比。
- **早停不能省**：不加早停时最后一轮验证集 mse 会高于标签方差，等于什么都没学到。
- **导出的是 float32 原始字节**（base64 包装），不是十进制文本，所以两边数值完全一致；
  一致性校验剩下的误差只是浮点累加顺序。
